Project Charter

The Why — purpose, scope, objectives, risks, and the path from informal trade to a regulated digital exchange.

Problem. Ghana's informal gold trade loses an estimated US$2.3 billion annually to leakage, fraud, tax evasion, and unbanked transactions. There is no single source of truth connecting licensed buyers, sellers, escrow, and regulators. AurumX exists to close that gap with verified counterparties, atomic escrow settlement, and tamper-evident audit trails.

Architecture Decision Records

ADR-001 Event-Driven SOA over Monolith
Context. The platform must scale across member onboarding, real-time trading, escrow, and regulator reporting independently — each with different load and compliance profiles.

Decision. Adopt an event-driven, service-oriented architecture with domain services (Member, Lot, RFQ, Trade, Escrow, Compliance, Audit) communicating via Kafka. A monolith would couple release cadences and complicate regulator-scoped audits.

Consequences. + Independent deployability, clearer audit boundaries, replayable event log. − Higher operational complexity, requires Outbox pattern (ADR-004) and distributed tracing.
ADR-002 Auth0 B2B for Identity
Context. Members range from multinational refiners (SSO with Entra ID) to rural cooperatives (mobile OTP). Regulators require MFA and lifecycle controls.

Decision. Standardize on Auth0 B2B for identity, federation, MFA, and RBAC — avoiding bespoke identity code.

Consequences. + Faster compliance, enterprise SSO, auditable access. − Vendor dependency; mitigated via standard OIDC and exportable user store.
ADR-003 Kafka (MSK) over RabbitMQ / SQS
Context. Audit requirements demand a durable, replayable, ordered event log spanning years. Escrow settlement and compliance alerting depend on event history.

Decision. Use AWS MSK (Kafka) as the event backbone. RabbitMQ/SQS lack durable multi-consumer replay at the required retention horizon.

Consequences. + Long-term retention, exactly-once semantics, replay for audit/SAR reconstruction. − Operational overhead; mitigated via MSK managed brokers.
ADR-004 Outbox Pattern for Atomic Event Publish
Context. A trade state change and the corresponding event must be atomic — never a committed trade without an event, never an event without a committed trade.

Decision. Write domain state and an outbox row in the same PostgreSQL transaction; a relay publishes to Kafka. This guarantees audit completeness.

Consequences. + No lost events, audit-ready. − Relay component to operate; idempotent consumers required.
ADR-005 Next.js PWA, no native apps in Phases 1–4
Context. Sellers operate on low-end Android devices with intermittent connectivity; buyers use desktops; compliance uses tablets. Native apps would triple delivery cost.

Decision. Ship a single Next.js PWA with offline-tolerant lot listing and background sync. Revisit native only if a Phase-5 offline requirement emerges.

Consequences. + One codebase, faster shipping, app-store-free distribution. − Push-notification limits on iOS; mitigated via SMS fallback for escrow events.

Security & Compliance

Seven security principles, the regulatory landscape, encryption strategy, and the audit cadence that keeps the platform trustworthy.

Seven Security Principles

S1
Least Privilege
Role-bound access via Auth0 RBAC. Just-in-time elevation. Quarterly access recertification.
S2
Defense in Depth
WAF, network segmentation, service mesh mTLS, secrets in AWS KMS / Secrets Manager.
S3
Encryption Everywhere
TLS 1.3 in transit, AES-256 at rest, envelope encryption for PII and audit payloads.
S4
Tamper-Evident Audit
Append-only, hash-chained events via Outbox + Kafka. Independent integrity attestation.
S5
Secure by Default
No secrets in code, SAST/DAST in CI, SBOM per release, signed container images.
S6
Privacy by Design
DPA 843 alignment, data minimization, purpose-limited retention, member consent ledger.
S7
Continuous Assurance
SOC 2 controls automated in CI, quarterly pen-tests, annual red-team, ISO 27001 readiness.

TerraPulze System Flow

An end-to-end map of user activities, data inputs, and shared technical ideas for mineral exploration target ranking and drilling.

User & Activity Flow by Stage

Geologists / Field Data Collectors

Data Aggregation & Ingestion

What Users Do

  • Collect physical and remote sensing data points from the ground.
  • Upload gathered datasets into the TerraPulze system for processing.
  • Instead of manually hunting for satellite bands online, users rely on the system to pull and synthesize imagery.

Data & Forms Filled

  • Geochemistry Data: Soil sample coordinates and chemical analysis (C-Log data).
  • Geophysics Data: Magnetic data (e.g., LOAA).
  • Satellite Imagery: Sentinel-2 (vegetation and moisture bands), Copernicus DEM (terrain data).
  • Geological Data: Lithology, structures, imported from sources like Wakusta's and One Geology.
  • Infrastructure Layers: Protected areas (from Forestry Commission), road networks.

Ideas & Concepts Shared

  • "Terra" means earth; "Pulze" means finding minerals the way you'd search for a pulse—identifying the lifeline of the earth.
  • Replacing the tedious, manual process of picking data points and hunting for satellite bands with an automated, mathematical algorithmic approach.
  • Machines can put the data "dots" together faster and more accurately than the normal human eye.
System AI / Exploration Managers

Automated Target Ranking & Gridding

What Users Do

  • System automatically processes combined data points to identify optimal drill locations.
  • System generates a grid overlay over the area, cutting lines (baselines and cross-lines) to show exact hole positions.
  • Managers view target percentages and confidence scores (e.g., 72% to 99% confidence).
  • Users click the "eye" button on targets to view detailed scientific reasoning for why a hole was placed there.

Data & Forms Filled

  • Project Overview Dashboard: Displays area measured, number of targets identified, average target scope, and confidence percentages.
  • Target Info Card: Shows target score, number of cells in cluster, estimated depth, and coordinates.
  • Automated Report: System generates a detailed explanation of the data synthesis on the fly (in under a minute).

Ideas & Concepts Shared

  • The system acts as a "partner" that gives detailed reasons for choosing one point over another, removing the need to manually write justification reports.
  • If probability is high, the system estimates depth; if unsure, it leaves depth out to avoid false predictions.
  • Targets are defined as specific drill holes, currently limited to surface positioning, but intended to expand to angles and deviations.
Geologists / Drilling Engineers

Drilling Parameter & Deviation Configuration

What Users Do

  • Review proposed drill targets and assess physical terrain constraints (e.g., surface disturbances, accessible paths for rigs).
  • Input desired drilling parameters to calculate deviation and error margins.
  • Toggle map layers (terrain, geology, roads, protected areas) to ensure the rig can physically access the proposed target location.

Data & Forms Filled

  • Hole Diameter Specs: E.g., 165mm, 89mm, 76mm (dictates when deviation begins).
  • Drill Angle Input: Angular vs. Vertical holes.
  • Rig & Rod Specs: Rod strength, drill string strain, feed force limits.
  • Target Depth: E.g., predicting depths between 100 and 300 meters.

Ideas & Concepts Shared

  • Precision Drilling Physics: Smaller holes (e.g., 76mm) deviate after 8 meters, especially in hard granite; larger holes (165mm) can go beyond 12 meters. The drill string becomes a "strain" that bends.
  • Angular vs. Vertical: Angular holes are better for deviation control; vertical holes in exploration are prone to missing targets.
  • Remote Control History: Referenced a 1999 remote-controlled drilling operation where the controller in Australia adjusted feed force every 30 minutes to prevent missing the target.
  • Terrain Access: The system must account for the fact that you can't always put a rig directly over the geological target; you must climb to an accessible point and drill at an angle to hit the vein.
Exploration Managers / Geologists

Re-analysis & Scenario Testing

What Users Do

  • Run background analyses while continuing other work in the system.
  • Add or remove specific data layers (e.g., run analysis with only Wakusta's data, then run it combined with One Geology data).
  • Compare reports to see how removing a specific data point impacts the overall target confidence and positioning.

Data & Forms Filled

  • Layer Toggle Controls: Switch between light, dark, satellite, terrain, and hyperspectral base maps.
  • Data Point Exclusion/Inclusion Forms: Selecting/deselecting specific geochemistry or geophysical datasets on the fly.

Ideas & Concepts Shared

  • Flexibility is key: geologists need to test hypotheses dynamically rather than being locked into one dataset.
  • The system should explain how adding or removing a data point impacted the analysis.
  • Need to segment exploration into phases (e.g., Phase 1: soil/auger work to locate the zone; Phase 2: deep drilling parameters).
Minerals Commission / Regulators

Regulatory Oversight & Monitoring

What Users Do

  • Access a plugin/portal to view exploration activities conducted by mining companies in real-time.
  • Review automated reports generated by the system instead of reading manual, subjective reports submitted by companies.

Data & Forms Filled

  • Compliance Dashboard: Viewing company activities, target outputs, and drilling parameters.

Ideas & Concepts Shared

  • Regulators shouldn't just sit in their offices waiting for paper reports; they should be able to monitor live activities so they can proactively schedule meetings before the companies even come to them.
  • Creating a standardized, home-grown Ghanaian solution to support local mining services and tech development.

How an Exploration Team Can Navigate This Flow

Based on the meeting insights, here is the step-by-step roadmap for an exploration team (like the Gold Fields pilot) to successfully use and validate the TerraPulze system:

1. Define the Scope & Fundamentals

Before touching the software, the team must clearly define what the system will solve. Does it end at placing the hole, or does it extend to planning the deviation profile? Ensure a dedicated, experienced geologist is paired with the computer science team to bridge the gap between computing and geological fundamentals.

2. Provide Real Historical Data

Move away from "made-up/test" data. The exploration team must supply real geochemistry, magnetic, and structural data (e.g., data from depths of 100 to 300 meters) to feed into the system for a valid trial run.

3. Integrate Structural Data for Angles

The current demo lacks structural data. The team must input structural geology data to allow the system to calculate the angle of planning, collar deviation, and target intersection, not just the surface X,Y position of the hole.

4. Conduct a Pilot Test on the Ground

Select an ideal candidate site (like a Gold Fields target). Run the system to generate targets, apply the deviation parameters (hole size, rod strength, angle), and physically mobilize a rig to test if the system's predictions hit the ore vein accurately.

5. Expand to Multinational Competitiveness

To compete with existing GIS software (like Hillfrog, KTIs), the team must use the pilot results to make the system robust. Add features like dispatch integration and underground drilling modules to scale the home-grown solution into an international system.

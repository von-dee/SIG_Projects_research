User flow

Five steps to release.

01

Select approved results.

Select only results with current QA approval. Confirm the client, project, and reporting scope for the compilation.

02

Compile intervals.

Compile each result with its original hole ID, from depth, to depth, method, unit, and any required qualifiers.

03

Generate & validate.

Generate a controlled COA version. Validate completeness and apply the formal release authorisation to the document.

04

Deliver.

Release through the approved delivery channel. Record the recipient, release time, and the immutable report identifier.

05

Handle amendments.

If corrected later, create a superseding COA that cites the original report and amendment reason. Never overwrite the released document.

Controls & hand-off

Immutability and exclusivity.

Released means permanent.

Once released, the Certificate of Analysis becomes an immutable record in the lineage graph. It represents a snapshot in time of the approved truth, completely insulated from subsequent laboratory changes.

Control · 01

A COA must never contain held, rejected, or superseded result versions. The reporting engine draws exclusively from the latest QA-approved state.

Control · 02

Released reports are immutable records in the lineage graph. They are permanent artifacts that can be cited, audited, and traced back to the original drill hole.

⎙
Corrections create superseding versions.

If an error is found after release, the original COA is not deleted or silently overwritten. A new version is generated, citing the original report and the reason for amendment. The client is informed of the supersession, preserving the integrity of the historical record.

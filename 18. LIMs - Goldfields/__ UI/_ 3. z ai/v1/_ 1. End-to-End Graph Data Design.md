This is a fascinating data architecture and UI challenge. By adopting **Decision D2 (A sample is a graph of transformations, not a row)**, the web application must transition from a traditional tabular database/UI to a **Directed Acyclic Graph (DAG)** visualizer and editor. 

Below is the end-to-end Graph Data Design and the corresponding Webflow/UI design to manage this geological sample lifecycle.

---

### PART 1: End-to-End Graph Data Design

To satisfy the traceability and mass-balance requirements, the database must be a Property Graph. Nodes represent physical materials; Edges represent transformations.

#### 1. Node Architecture (The "What")
Nodes represent physical entities at a specific point in time. They have a unique ID, current mass, and location/status.

*   **`MaterialNode` (Generic base)**
    *   `node_id` (UUID)
    *   `material_type` (Field Core, Dried Sample, Crushed Split, Pulp, Assay Charge, Lead Button, Prill)
    *   `current_mass` (grams)
    *   `status` (Active, Consumed, Retained, Discarded)
    *   `location` (e.g., Shelf A, Tray 07 Pos 23)
*   **`ContextNode` (Metadata)**
    *   `HoleInterval`: `{ hole_id, from_m, to_m }`
    *   `Consumable`: `{ type: Flux/Cupel, lot_number }`
    *   `Equipment`: `{ type: Furnace/Crusher, equipment_id }`

#### 2. Edge Architecture (The "How" - Mass Balance)
Edges represent the operations. Because mass can split or merge, an edge connects one or more parent nodes to one or more child nodes (Hypergraph modeling, often implemented via an intermediate "Operation" table in relational DBs, or native edges in graph DBs).

**Edge Properties:**
*   `operation` (Drying, Crushing, Splitting, Pulverising, Weighing, Fusing, Cupelling)
*   `mass_in` (Sum of parent masses)
*   `mass_out` (Mass of the resulting child)
*   `mass_reject` (Mass retained or lost)
*   `operator_id`
*   `timestamp`
*   `metadata` (JSON for specific checks like P80, tray position)

#### 3. Visualizing the Graph Lifecycle (The DAG)

```text
[Context: Hole A, 10-15m] 
       │ (origin)
       ▼
[Field Sample: 3.0kg] ──────(Op: Dried)─────► [Dried Sample: 2.8kg] 
                                            │ (retain: 0kg, loss: 0.2kg H2O)
                                            ▼
                                   (Op: Crushed & Split)
                                            │ 
                     ┌──────────────────────┼──────────────────────┐
                     ▼                      ▼                      ▼
          [Coarse Reject: 2.7kg]     [Split: 100g]               (Loss/Dust)
          (Status: Retained)               │
                                            ▼
                                    (Op: Pulverised)
                                            │
                     ┌──────────────────────┼──────────────────────┐
                     ▼                      ▼                      ▼
          [Pulp Reject: 90g]        [Pulp: 10g]                 (Loss)
          (Status: Retained)             │
                                          │──(Op: Weigh Charge)──►[Assay Charge: 50g]
                                          │                        │
                                          │                        ▼
                                          │                   (Op: Fusion)
                                          │                        │ (Flux Lot #123)
                                          │                        ▼
                                          │                   [Lead Button: 30g]
                                          │                        │
                                          │                        ▼
                                          │                   (Op: Cupellation)
                                          │                        │ (Cupel Lot #456)
                                          │                        ▼
                                          │                   [Prill: 0.00005g]
                                          │                        │
                                          │                        ▼
                                          │                   (Op: Finish/Calc)
                                          │                        │
                                          └────────────────────────┴──► [RESULT: 1.0 g/t Au]
```

*Note on Composites:* If a metallurgical sample combines two drill holes, the graph simply features two `Field Sample` nodes pointing their edges into a single `Composite Sample` node, perfectly preserving mass balance and lineage.

### PART 2: Webflow & UI Design

The web application must serve two masters: **Lab Technicians** (who need fast, sequential data entry) and **Geologists/Auditors** (who need visual traceability and mass-balance validation).

#### A. Information Architecture (Site Map)
1.  **Dashboard:** Overview of active batches, QA/QC alerts, mass-balance failures.
2.  **Prep Workflow (Sequential UI):** Step-by-step entry for Drying -> Crushing -> Pulverising.
3.  **Fire Assay Workflow (Batch UI):** Tray management, Fusion, Cupellation, Weighing.
4.  **Sample Graph Explorer (The core traceability tool):** Visual node-based exploration of any sample.
5.  **Admin:** Equipment, Consumable Lots, User Management.

#### B. End-to-End User Flow (The Technician's Journey)

**Step 1: Sample Intake & Preparation (Webflow: Card-based sequence)**
*   **UI:** A Kanban-style board or sequential stepper. 
*   **Action:** Tech scans barcode on the core tray. Enters `gross_mass` (3kg). 
*   **Action:** Tech dries sample. Enters `dry_mass` (2.8kg). UI immediately displays `Mass Delta` (6.6% loss). If loss > 10%, UI flashes red, demanding a reason code.
*   **Action:** Crushing & Splitting. Tech enters mass of retained reject and mass of split sent to pulverizing.
*   **P80 Check:** UI presents a modal to input P80 microns before allowing progression to Pulp stage.

**Step 2: Pulp Management (Webflow: Grid view)**
*   **UI:** Data table of active pulps. 
*   **Action:** Tech selects pulps to be sent to Fire Assay. UI auto-generates `Assay Charge` nodes (50g) linked to the parent `Pulp` node.
*   **Crucial Logic:** The UI explicitly states: *"Pulp [ID] original mass: 10g. Charge taken: 50g. Remaining: 50g. Pulp retained."*

**Step 3: Fire Assay Workflow (Webflow: Visual Tray Map)**
*   **UI:** A visual grid representing the furnace tray (e.g., 5x10 grid).
*   **Action:** Tech drags 50g charges into grid positions (e.g., Tray 07, Pos 23). The UI saves this as spatial metadata on the `Assay Charge` node.
*   **Action:** Tech selects Flux Lot and Furnace ID from dropdowns. Clicks "Execute Fusion."
*   **Action:** Tech enters weight of Lead Button. Graph updates: `mass_out` = 30g, `mass_reject` (slag) = 20g. Slag retained flag = True.

**Step 4: Cupellation & Finish (Webflow: Microbalance Integration)**
*   **UI:** Form linked to a microbalance via RS232/USB.
*   **Action:** Tech places prill on balance. UI auto-populates `Prill weight` in micrograms. Tech selects Cupel Lot.
*   **Action:** System calculates final grade (Au g/t) based on the original 50g charge. The result node is created, closing the graph.

#### C. The "Sample Graph Explorer" UI (For Auditors & Geologists)

This is the visual manifestation of Decision D2. 

*   **Layout:** Full-screen canvas using a library like React Flow or D3.js.
*   **Interaction:** 
    *   User searches for a Hole ID (e.g., "Hole A, 10-15m") or a Result (e.g., "Grade > 5g/t").
    *   The screen renders the origin node. 
    *   User clicks "Expand Lineage." The graph dynamically renders outward, showing splits, rejects, and the final prill.
*   **Visual Mechanics:**
    *   **Nodes:** Color-coded by stage (Green = Field, Yellow = Prep, Orange = Pulp, Red = Fire Assay, Blue = Result).
    *   **Edges:** Thickness proportional to mass. A thick line for 3kg, a thin line for 50g.
    *   **Mass Balance Indicators:** If `mass_in` - `mass_out` - `mass_reject` != 0, the edge glows red. A tooltip explains the discrepancy.
*   **Data Panes:** Clicking any node opens a right-hand sidebar displaying all properties (P80, tray position, operator, timestamp, flux lot).

### Why this design succeeds:
1.  **Mass Balance as a UI Feature:** By making mass calculations visible at every step, data entry errors are caught immediately, not weeks later during QA/QC.
2.  **Infinite Flexibility:** Because the model is a graph, if a lab decides to do a duplicate assay from the *same pulp*, the UI simply spawns a new 50g `Assay Charge` node from the existing `Pulp` node. A flat table breaks here; the graph thrives.
3.  **True Traceability:** An auditor can visually click from the final "1.5 g/t" result, walk backward through the prill, the cupel, the lead button, the tray position, the 50g charge, the pulp, the split, all the way back to a specific meter of drill core.

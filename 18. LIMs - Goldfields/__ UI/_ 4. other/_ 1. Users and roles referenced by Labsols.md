## Users and roles referenced by Labsols

Their own materials mention training being role based, covering various user levels from lab manager to technician to management, with tutorial documents for each operational layer, module, and access level. The FAQ adds that role-based training (e.g. admin, analyst, manager) is standard practice, with the vendor providing go-live support.

Beyond internal lab staff, their reporting/notification features imply several external-facing roles too — the system sends optional notification emails on stage and status changes to the Lab, Coordination, Client, Agent, Consultant, and Vessel (that last one is specific to their marine/oil-condition-monitoring vertical).

Putting that together, the roles are roughly:

| Role | Typical scope |
|---|---|
| **System Admin** | User/role management, module configuration, instrument integration, workflow/SOP setup |
| **Lab Manager** | Oversight dashboards, KPI/BI reporting, approval of final results, resource allocation |
| **Analyst / Technician** | Sample login, testing, entering raw results, flagging failures |
| **QC / Reviewer** | Reviewing/approving results before release, statistical process control (SPC) checks |
| **Coordination / Front Office** | Sample scheduling, client communication, invoicing hooks (via Accounts integration) |
| **Client / Agent / Consultant (external, via Customer Portal)** | Submitting samples, viewing status, downloading reports/COAs |
| **Vessel/Site contact** (industry-specific, e.g. marine/oil) | Receiving test notifications relevant to their equipment/site |

## Typical user flows (inferred from feature descriptions)

**Sample lifecycle (Analyst/Technician → QC → Manager):**
1. Sample registered/logged in (single or batch, with scheduling) — end-to-end sampling process in single or multiple batches including scheduling
2. Sample tracked through a dashboard where users can drill into a sample to interact with or investigate it further, with instrument integration providing automated result capture
3. Results outside acceptable limits are auto-flagged — the system is largely automated so most results fall within acceptable limits, with failures filtered and highlighted to trigger follow-up investigation
4. Any manual data change is logged — an annotation feature generates a log file showing who changed data and when
5. Report generated and released, with notifications sent to Lab, Coordination, Client, Agent, Consultant, and Vessel on status changes

**Reporting/analytics flow (Manager/Analyst):**
- Choose from General Search, Multi-Criteria Search, Historical Search, Samples Count, or Samples-in-Progress reports, or use the Ad-hoc Query Tool, which lets end-users construct complex database queries by dragging and dropping fields, with no SQL knowledge required
- Optionally schedule recurring report emails to specific recipients

**Client-facing flow (Customer Portal):**
- External clients log into a self-service portal for a user-friendly, secure lab management experience with regulatory compliance and reporting/analytics access, rather than emailing the lab directly

If you want the exact role/permission matrix and step-by-step screens (login → dashboard → sample entry → approval, etc.), that level of detail is in their gated user guide / demo materials rather than public pages — worth requesting directly from Labsols or checking if you already have vendor-provided documentation from your implementation.

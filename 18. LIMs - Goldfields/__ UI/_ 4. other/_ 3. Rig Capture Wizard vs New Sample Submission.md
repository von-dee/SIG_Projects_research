Short version: **Rig Capture is about recording samples as they're created; Sample Submission / COC is about recording them as they leave your hands.** They're two stages of the same chain.

| | **Rig Capture Wizard** | **New Sample Submission / COC** |
|---|---|---|
| **When** | At the rig/face, while sampling is in progress | At dispatch, once bags are sealed and ready to ship |
| **Purpose** | Capture the interval data and create the sample's identity | Transfer custody of already-identified samples to the lab |
| **Creates** | Sample records in the database (hole, from/to, type, field sample ID) and typically the tag/barcode | A submission batch + custody events (collector, seal ID, transfer time, signatures) |
| **Validates** | Depths against the sampling plan — overlaps, gaps, ID uniqueness | Bag/seal condition, that every ID reconciles, dispatch completeness |
| **Used by** | The sampler/geologist cutting the interval | The dispatcher/sample custodian |
| **End state** | Samples exist in the system, not yet dispatched | Custody open → closes when the lab acknowledges intake |

**How they connect:** you rig-capture first, then submit. The submission pulls in the sample IDs that already exist — you're not re-entering intervals, just adding the custody layer (seal, condition, carrier, signatures) per bag. That maps directly onto the SOP doc above:

- Rig Capture ≈ steps 1–3 (locate interval, cut/collect, bag and tag)
- Submission/COC ≈ steps 4–6 (inspect, complete the form, seal and dispatch)

And the SOP's "batch handling" rule is exactly how the submission side behaves: the submission is the batch, but each bag stays an individual member line with its own ID, interval, and seal — the dispatch never merges them.

One practical implication: if a sample was never rig-captured, some systems let you add it manually during submission — but then plan validation and duplicate-ID checks happen at submission time instead of at capture, which is a worse place to discover a bad interval.

Caveat: these labels vary between systems (MX Deposit, Track'em, acQuire, custom LIMS…), so the exact fields and sequence differ. If you tell me which platform you're on, I can be more specific about its workflow.

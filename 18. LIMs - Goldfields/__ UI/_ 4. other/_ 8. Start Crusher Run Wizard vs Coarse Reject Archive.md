Two pairs, but they're really one lifecycle — the **write side** (make rejects) and the **read side** (find them again). Short versions:

- **Start Crusher Run Wizard vs Coarse Reject Archive:** the wizard is the guided *process* that crushes and splits dried samples; the archive is the standing *inventory* the rejects land in. Writer vs destination.
- **Reject Locator vs New Crusher Run:** the locator is a *read* tool — find where a reject is shelved; New Crusher Run is a *write* action — open a run record manually. Query vs creation.

## Pair 1 — the process vs the store

| | **Start Crusher Run Wizard** | **Coarse Reject Archive** |
|---|---|---|
| **What it is** | Guided workflow to open and work a crusher/split run | Standing register of retained coarse rejects (and/or the physical store it maps) |
| **Operates on** | Dried samples from the queue — run members | Reject children — shelved bags |
| **Direction** | Write/process | Write destination, then long-lived record |
| **Answers** | "Which dried samples is this run processing, on which equipment, with what mass balance?" | "What reject material do we hold, from which parents, shelved where?" |
| **Lifecycle** | One run; closes at sign-off | Entries outlive the run — retention, retrieval, consumption, disposal |

## Pair 2 — the query vs the creation

| | **Reject Locator** | **New Crusher Run** |
|---|---|---|
| **What it is** | Search/find over the archive | Blank, manual creation of a run record |
| **Direction** | Read/navigation — creates nothing | Write/create |
| **Answers** | "Where physically is the reject for parent X?" | "Open a run for these samples without the guided flow" |
| **Used when** | Pulling material for duplicates, check assays, umpire re-assay | Exception path: off-queue samples, reprocessing, re-splits |

## How the four connect

```
Start Crusher Run Wizard ──(or)── New Crusher Run     ← open the run (guided vs manual)
              ↓
   crusher/split run + member lines
              ↓ each member produces
   work split ──────────────→ pulverising queue
   reject child ─── shelved ─→ Coarse Reject Archive  ← the standing store
                                ↘ Reject Locator      ← find it later
                                    ↘ pull → possible re-split → back into a run
```

Mapped onto doc 04: the wizard covers **steps 1–3** (readiness, equipment, method, members); the archive is where **step 4**'s records live (bag, seal, shelf location); the locator is what operationalizes the outcome — "a *retrievable* reject is retained" is only true if the locator can find it. And New Crusher Run is the alternate door into steps 1–3, exactly parallel to how New Sample Intake Log sat next to the Shipment Intake Wizard — same design pattern, second occurrence in your system.

Three consequences worth knowing:

- **The locator is only as good as the archive's locations.** This is why "missing reject location blocks completion" is a hard control, not a nag: a reject without a recorded shelf location is retained in name only — nobody can pull it in two years for a check assay.
- **The archive outlives everything.** The run closes at sign-off, the work split gets consumed in analysis, but the reject entry persists for the retention period. When you're auditing or doing disposal review, the archive — not the worksheets — is your record.
- **The locator can loop back into a run.** Pull a reject for a re-split or duplicate program, and that material becomes input to a new run — the reject becomes a *parent*, growing the lineage tree another tier.

**Practical difference when clicking around:** tray of dried samples to process → wizard. Inventory count, disposal review, audit → archive. QC wants duplicates on ten holes → locator. One held/resolved sample or a re-split job → New Crusher Run.

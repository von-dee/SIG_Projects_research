## Critical Dependency Map

```text
Venue capacity + safety approval
  -> sellable booths / rooms -> contracts -> exhibitor build + meeting allocation

Protocol precedence + security rules
  -> VIP profiles -> seating / transport / holding rooms -> stage and arrival plans

Access tier definitions
  -> registration pathways -> credential production -> gate decisions / staffing

Commercial package approval
  -> sponsor commitments -> speaker slots / guest passes / branding / hospitality

Confirmed participants + agenda
  -> dietary forecast / matchmaking / mobile agenda -> room and F&B operations

Approved stage assets + speaker availability
  -> rehearsal -> run of show -> live broadcast and attendee communications

Verified operational data
  -> closeout reports -> stakeholder value proof -> next-year improvements
```

### Dependency rules

- Do not release a downstream promise before its upstream capacity, owner, and policy are approved.
- Any upstream change must identify affected contracts, people, rooms, badges, budget, communications, and safety plans before approval.
- When a dependency is uncertain, publish a controlled provisional status and a decision deadline rather than treating it as confirmed.

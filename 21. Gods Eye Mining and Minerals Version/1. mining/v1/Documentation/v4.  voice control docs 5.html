ML-DOC-003 · VOICE CONTROL MANUAL · REVISION A

TALK TO IT

The microphone is a front-end, not a privilege. Every spoken command resolves to the exact same local parser the keyboard uses — no keys, no cloud account, and every utterance has a text twin, so nothing is ever voice-only. This manual documents the v0.2 voice module: the pipeline, the states, 14 user flows, the 33-entry grammar, and the one-function wiring that adds it to the console.

VC-00OVERVIEW — TALK TO ITmanual.html#console

What voice control is in MOTHERLODE — and what it deliberately is not.

The console already understands natural phrases through its local parser: track grasberg, show lithium, fly to chile. The voice layer simply removes the keyboard from that path. Speech in, transcript out, grammar match, parser, action — plus a terse spoken reply so the operator never has to look at the screen.

THE FOUR VOICE JOBS

  • ▸ DIRECT IT — camera and targeting by mouth: fly, track, zoom, reset. (→ VC-03)
  • ▸ QUERY IT — analyst questions against the local dataset: counts, quotes, assays, context. (→ VC-04)
  • ▸ OPERATE IT — the whole console hands-free: layers, sensors, detection, pit mode, tours. (→ VC-05 → VC-07)
  • ▸ CONTROL IT — the voice session itself: wake, cancel, mute, repeat. (→ VC-02, VC-11)
DESIGN RULE — THE TEXT TWIN Every entry in the grammar table below carries a text twin: the console command that does the identical thing. If the mic is denied, missing, or simply unwanted, nothing is lost. Voice is an input method, never a dependency — the opposite of a feature you pay per minute to use.

—VOICE GRAMMARmanual.html#console

33 entries, four jobs. YOU SAY is speech; the TEXT TWIN is the console command that does the identical thing — click any twin to copy it. Spoken replies are capped at twelve words.

SPOKEN REPLY STYLE GUIDE

  • ▸ Subject + state, at most twelve words — Tracking Grasberg. Copper and gold. Indonesia.
  • ▸ Numbers spoken naturally, never digit strings.
  • ▸ Every spoken line mirrors into the console log — spoken words are always also written.
  • ▸ The SILENCE toggle kills TTS without touching any other function.

—PRIVACY & THE LINEmanual.html#sources

Where the audio goes, and the rule that never bends.

  • ▸ Audio streams to the browser speech engine and is gone — nothing is recorded, stored, or attached to any account.
  • ▸ Chrome and Edge may route engine audio through the vendor speech service. The session panel (VC-13) says so plainly. If that is unacceptable, use the text console — the two are feature-equal.
  • ▸ Firefox ships no SpeechRecognition → the chip reads UNSUPPORTED, and nothing degrades.
  • ▸ The wake gate runs on transcript hypotheses inside the page — there is no always-on hardware keyword.
  • ▸ Auto-mute on tab blur: the listener never runs while you are somewhere else.
THE LINE The grammar contains no person-search intents — no names, no faces, no individuals — and it never will. This console models sites, infrastructure and public data. People are not a query type here.

—TROUBLESHOOTINGmanual.html#troubleshooting

SymptomCause & fix
Chip red — DENIEDPermission blocked. Re-grant via the browser address-bar site-settings icon, then press MIC once more (VC-10 E1).
Wake never triggersSay the full phrase, not just “lode”. Check the profile — strict is harder to wake. Reduce background noise.
Wake fires constantlySwitch to the strict profile; a false-wake storm auto-suggests it (VC-14 E1).
Commands resolve to nonsenseRead the raw transcript in the log — it is always printed. Use the correction loop or the dictation fallback (VC-08).
The console seems to answer itselfHalf-duplex normally prevents this. If it persists, use headphones or the SILENCE toggle (VC-12).
Voice does nothing on FirefoxNo engine in that browser — UNSUPPORTED by design. The text console has full parity.
Permission prompt never appearsPreviously blocked at the browser level. Clear the site permission and reload.

—DEV WIRINGmanual.html#extending

How little stands between console v0.1.1 and the voice layer — one function, because voice is a front-end to the parser.

// one function, zero keys — voice becomes a front-end to the parser
const SR = window.SpeechRecognition || window.webkitSpeechRecognition;
if (SR) {
  const rec = new SR();
  rec.continuous = true;   rec.interimResults = true;  rec.lang = "en-US";
  rec.onresult = e => {
    const t = e.results[e.results.length-1][0].transcript.trim();
    // wake gate lives here — score the hypothesis, open the capture window
    parseCmd(t);           // the exact same parser the keyboard uses
  };
  rec.onerror = ev => setMicState(ev.error === "not-allowed" ? "DENIED" : "OFF");
  $("#btn-mic").onclick = () => rec.start();
}

// spoken replies — one line
const say = s => speechSynthesis.speak(new SpeechSynthesisUtterance(s));

UC-00HOW TO READ A FLOW

The notation used in every diagram below.

OPERATORThe human at the console — drags, clicks, types, decides.
Badge: USER — green rail
SYSTEMThe console itself — renders, flies, tracks, parses, recolors.
Badge: SYS — amber rail
SIMULATED FEEDThe local generators — wire, prices, seismicity. Act on their own clocks.
Badge: FEED — cyan rail
DEVELOPERExtends the console — adds mines, commodities, tours, sensors.
Badge: DEV — magenta rail
RECIPIENTReceives a share link and reconstructs the view of the sender.
Badge: RCPT — violet rail
  • ▸ Numbered nodes = main success scenario, top to bottom, in temporal order.
  • ▸ IF boxes (dashed) = branch points attached to a step — conditions that reroute the flow.
  • ▸ E# rows = alternate paths & exceptions listed after the flow.
  • ▸ POSTCONDITION = the state the world must hold when the flow succeeds.
  • ▸ Green command chips copy to clipboard — paste straight into the console.

UC-25END-TO-END SESSION TRACE

A typical first session — how the flows chain in practice. Order is habitual, not mandatory.

READING THE CHAIN Boot configures → layers scope the survey → discovery finds a contact → tracking locks it → pit mode dives it → sensors re-skin it → the console automates it → a tour shows the district → the wire interrupts with a lead → a price query frames it → a share link hands the whole session to someone else. Twenty-eight minutes, zero keys.

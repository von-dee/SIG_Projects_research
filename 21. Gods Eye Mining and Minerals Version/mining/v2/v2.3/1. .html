Extending the Globe

Add Your Own Data Sources & Layers

God's Eye View is a vanilla-JS / CesiumJS / Vite canvas — every layer is its own module under src/data/. This manual walks through the full lifecycle of a new layer: pick a feed, pick a visual primitive, write the module, register it, wire the UI, optionally broker a key through the server, and (if you want) hand the agent a voice tool so you can talk to it.

🟢 no key required to start 🟡 free-key upgradeable 🔴 metered (server-brokered) vanilla JS · no framework MIT licensed

00Why extend

The shipped globe already fuses fifteen live and bundled sources — flights, ships, satellites, earthquakes, CCTV, transit, fires, radio, space missions, and more. But the project is explicit about its purpose: "every layer here is a pattern you can point at your own data sources." The maintainers actively want you to bolt things on — community PRs already include ALPR cameras and SDR radio, and the README opens issues for missing layers.

Typical reasons people extend the globe:

  • Reconstruct an event — flood paths, earthquake shake maps, wildfire perimeters from Planet/Viirs, plotted against ground imagery.
  • Monitor your own infrastructure — fleet GPS, sensor telemetry, IoT positions, ship reporting from your own AIS source.
  • Add a city pack — your transit authority's GTFS-Realtime feed, your local CCTV, your bikeshare.
  • Swap a feed — replace a free/limited provider with a paid one (satellite AIS, Sentinel hub, commercial SAR).
  • Reskin reality — custom GLSL sensor looks, custom 3D models per contact class.
The line, restated God's Eye View models events, assets, infrastructure, and systems — not named people. Anything face-recognition, person-tracking, or individual-search crosses the project line and won't merge. Build for systems and signals, not for surveillance of individuals.

01Architecture at a glance

The app is intentionally framework-free: vanilla JavaScript, CesiumJS for the 3D globe, Vite for the dev server, and the OpenAI Realtime API for voice. That means there's no React reconciliation to fight, no store middleware to learn — a layer is just a module that talks to the Cesium viewer and registers itself with a tiny orchestrator.

02Anatomy of a layer

A layer is a plain ES module exporting a single object literal. The orchestrator in src/data/ calls into this contract — it is small, but every field is load-bearing. 

// src/data/myLayer.js
export const myLayer = {
  // ── Identity ───────────────────────────────────────
  id: 'my-layer',                  // stable string, used in share URLs
  name: 'My Layer',               // display name in the LAYERS panel
  category: 'live',              // 'live' | 'static' | 'simulated'
  description: 'One-line summary shown in the panel.',
  icon: '📡',                    // emoji or path to an SVG

  // ── Capability flags ─────────────────────────────
  defaultEnabled: false,
  requiresKey: null,              // null | 'aisstream' | 'tomtom' | 'yourkey'
  refreshMs: 30000,               // polling interval; null for static
  maxEntities: 5000,               // hard cap, viewport-bounded recommended

  // ── State (private) ──────────────────────────────
  _viewer: null,
  _entities: new Map(),
  _enabled: false,
  _lastFetch: 0,

  // ── Lifecycle ─────────────────────────────────────
  async init(viewer, ctx) {
    this._viewer = viewer;
    this._ctx = ctx;              // { keys, locale, voice, shareState }
    this._dataSource = await this._buildSource();
  },

  async enable() {
    if (this._enabled) return;
    this._enabled = true;
    await this._refresh();
    this._startLoop();
  },

  async disable() {
    this._enabled = false;
    this._stopLoop();
    for (const e of this._entities.values()) this._viewer.entities.remove(e);
    this._entities.clear();
  },

  // ── Per-frame tick (called by orchestrator) ──────
  update(dt, now) {
    // interpolate positions, cull off-screen, project headings
    for (const e of this._entities.values()) this._tickEntity(e, dt, now);
  },

  // ── Fetch & ingest ────────────────────────────────
  async refresh() { return this._refresh(); },

  // ── Selection / contacts ───────────────────────────
  onTrack(entity) { /* optional: surface telemetry card */ },
  contactsNearby(lat, lon, radiusKm) { /* for the 250km Contacts roster */ },

  // ── Share-link state ──────────────────────────────
  serializeState() { return { filters: this._filters }; },
  deserializeState(s) { if (s?.filters) this._filters = s.filters; },

  // ── Internal helpers (private) ────────────────────
  async _buildSource() { … },
  async _refresh() { … },
  _tickEntity(e, dt, now) { … },
};

The orchestrator handles all the cross-cutting concerns: per-frame update() dispatch, share-link (de)serialization, contacts roster queries, and dispatching clicks to the right layer's onTrack(). You write the layer; the orchestrator wires it to the world.

04Data patterns

Existing layers fall into four shapes. Each has its own ingestion rhythm:

PatternExamplesCadenceNotes
Static bundled datacenters, dams, submarine cables Loaded once at init from local_data/ GeoJSON provenance per folder; ship the license alongside the data
Polling REST OpenSky, USGS, NASA FIRMS, Launch Library Every refreshMs; render one interval behind real time Use a credit governor — never call more than the provider allows
Streaming WebSocket AISStream (ships) Continuous; batch-ingest every ~1s Server-brokered when a key is involved; browser-only when keyless
Stateless propagation CelesTrak TLEs → SGP4 → satellites Re-fetch TLE daily; propagate per-frame GMST realignment keeps orbit rings locked; never drift, never flicker
Smooth motion from choppy data Live feeds arrive every 15–30s. The globe renders one interval behind real time and interpolates between known fixes; dead reckoning fills the gaps. When you implement update(dt, now), interpolate — don't snap.

05Quickstart

If you can clone, install, and open a single file, you can ship a layer in an evening. The whole flow reduces to nine steps.

  1. Pick a feed

    Decide what you want on the globe and which of the four data patterns it matches.

  2. Scaffold the module

    Create src/data/myLayer.js from the anatomy template above.

  3. Implement the lifecycle

    init, enable, disable, update, refresh.

  4. Register in main.js

    Add the layer to the orchestrator's registry; it now appears in the LAYERS panel.

  5. Wire the UI

    Toggle, filter chips, contextual menu entries — all declarative against the registry.

  6. Bundle static data

    If you ship a dataset, drop it in src/data/local_data/ with provenance + license.

  7. Add an API key (optional)

    Broker private keys server-side; only Google Maps & Cesium ion live in the browser.

  8. Add a voice tool (optional)

    Let users say "turn on my layer" or "what's the nearest contact on my layer?"

  9. Serialize share state

    So a URL can round-trip your layer's filters and tracked contact.

The next sections walk each step in detail.

06Step 1 · Pick a feed

Before writing any code, classify your feed. The classification dictates everything downstream: whether you need a key, whether the call is browser-side or server-brokered, how often you refresh, and which visual primitive fits.

Decision matrix

Feed typeAuthWhereLayer categoryExample
Public, keyless🟢 noneBrowserliveUSGS earthquakes, adsb.lol
Public, free key🟡 free keyBrowser (restrict at provider) or serverliveAISStream, FIRMS, TomTom

Hard rule If your feed needs a private key — even a free one — broker it through the server-side proxy. The browser may only ever see a Cesium ion or Google Maps key, both restricted at the provider. Server brokering applies SSRF protection, response caps, and sanitized errors.

Keep the file small and one-purpose. If you have a parser, a renderer, and an ingestor, split them into sibling files and import — the existing layers do exactly this. There is no build step magic; Vite resolves relative imports natively.

08Step 3 · Implement the lifecycle

enable / disable

async enable() {
  if (this._enabled) return;
  this._enabled = true;
  await this._refresh();          // first ingest
  this._loop = setInterval(() => this._refresh(), this.refreshMs);
},

async disable() {
  this._enabled = false;
  clearInterval(this._loop);
  for (const e of this._entities.values()) this._viewer.entities.remove(e);
  this._entities.clear();
},

refresh — fetch, normalize, upsert

async _refresh() {
  const url = 'https://api.example.com/v1/positions';
  let data;
  try {
    data = await fetchJson(url, { timeoutMs: 8000 });
  } catch (err) {
    console.warn('[shipSpotters] refresh failed', err);
    return;                       // keep last known good state
  }

  const next = new Map();
  for (const fix of data.vessels) {
    const id = fix.mmsi ?? fix.icao ?? fix.id;
    if (!id) continue;

    let e = this._entities.get(id);
    if (!e) {
      e = this._viewer.entities.add({
        id: `sp-` + id,
        billboard: { image: './icons/ship.svg', heightReference: Cesium.HeightReference.NONE },
        properties: new Cesium.PropertyBag({ fix, trail: [] }),
      });
    }

    // update interpolated target — the update() loop lerps toward this
    e.properties.fix.setValue(fix);
    e.properties.trail.getValue().push([fix.lon, fix.lat, fix.alt ?? 0]);
    next.set(id, e);
  }

  // drop contacts that disappeared
  for (const [id, e] of this._entities) {
    if (!next.has(id)) this._viewer.entities.remove(e);
  }
  this._entities = next;
  this._lastFetch = performance.now();
},

update — per-frame interpolation & heading projection

update(dt, now) {
  if (!this._enabled) return;

  for (const e of this._entities.values()) {
    const fix = e.properties.fix.getValue();
    if (!fix) continue;

    // dead-reckon between known fixes (15–30s data, smooth on screen)
    const t = Math.min(1, (now - this._lastFetch) / this.refreshMs);
    const pos = this._lerpPosition(e._prev, fix, t);

    e.position = Cesium.Cartesian3.fromDegrees(pos.lon, pos.lat, pos.alt);

    // shared helper — keeps headings world-stable across every camera angle
    projectHeading(e, fix.heading ?? 0);
  }
},

_lerpPosition(a, b, t) {
  if (!a) return b;
  return {
    lon: a.lon + (b.lon - a.lon) * t,
    lat: a.lat + (b.lat - a.lat) * t,
    alt: (a.alt ?? 0) + ((b.alt ?? 0) - (a.alt ?? 0)) * t,
  };
},

onTrack — surface the telemetry card

onTrack(entity) {
  const fix = entity.properties.fix.getValue();
  return {
    title: fix.name ?? fix.callsign ?? 'Unknown contact',
    rows: [
      ['MMSI', fix.mmsi ?? '—'],
      ['Speed', `${fix.sog ?? 0} kn`],
      ['Heading', `${fix.heading ?? 0}°`],
      ['Destination', fix.destination ?? '—'],
    ],
    actions: [
      { label: 'Cockpit', kind: 'cockpit' },     // if your layer supports it
      { label: 'Nearest CCTV', kind: 'cctv-handoff' },
    ],
  };
},

09Step 4 · Register in main.js

src/main.js bootstraps the globe and hands the layer registry to the orchestrator. Adding your layer is a two-line change. 

// src/main.js
import { flights }       from './data/flights.js';
import { vessels }       from './data/vessels.js';
import { earthquakes }  from './data/earthquakes.js';
// …
import { shipSpotters }  from './data/shipSpotters.js';   // ← add

const LAYERS = [
  flights,
  vessels,
  earthquakes,
  // …
  shipSpotters,                              // ← add
];

async function bootstrap() {
  const viewer = await buildViewer({ tiles, terrain });
  const orch  = await orchestrator.create({ viewer, layers: LAYERS, ctx });
  ui.attach(orch);   // LAYERS panel reflects the new entry automatically
}

bootstrap();

The orchestrator is the single source of truth for what's on the globe. UI panels, the contacts roster, the HUD summary, the voice agent, and share-link (de)serialization all read from it — so once you register, every other system sees your layer with no further wiring.

10Step 5 · Wire the UI

The LAYERS panel on the left side of the screen is generated from the registry — your layer's name, icon, and description render automatically. For richer controls (filter chips, density sliders, sensor-style color pickers), declare them in the layer object: 

controls: [
  { id: 'class', label: 'Class', type: 'select',
    options: ['all', 'tanker', 'cargo', 'passenger'] },
  { id: 'density', label: 'Density', type: 'range', min: 0, max: 100, step: 5 },
  { id: 'trails', label: 'Trails', type: 'toggle' },
],

onControl(id, value) {
  if (id === 'class') this._filterClass = value;
  if (id === 'density') this._density = value;
  this._refresh();   // re-query with the new filter
},

Control types currently understood: toggle, range, select, button. The orchestrator renders them in the LAYERS panel under your layer's row, persists values to localStorage, and round-trips them through share links via serializeState.

Contacts roster If your layer tracks moving things, implement contactsNearby(lat, lon, radiusKm) returning a sorted array. The 250 km Contacts roster automatically merges your results with flights, vessels, and installations — no UI work needed.

11Step 6 · Bundle static data

For non-streaming datasets — your own list of sensors, a curated set of points of interest, a disaster reconstruction — drop a file under src/data/local_data/. Each folder carries its own README.md with provenance and license; the project's DATA_SOURCES.md rolls these up.

src/data/local_data/ ├── datacenters/ │ ├── datacenters.geojson │ └── README.md # provenance, license, last-updated ├── dams/ ├── submarine_cables/ └── nepal_flood_2024/ your reconstruction ├── usgs_m52.geojson ├── flood_path.geojson ├── observer_clips.geojson # lat/lon/link for each social clip └── README.md

Load it once at init:

async _buildSource() {
  const res = await fetch('./data/local_data/nepal_flood_2024/usgs_m52.geojson');
  return res.json();
},
Reconstruction pattern The maintainer's Nepal flood walkthrough is the canonical example: pull public data (USGS, Planet/Viirs, officially reported sources), plot the path, attach observer video clips as billboarded pins along the timeline. The same shape works for wildfire perimeters, quake shake maps, and storm tracks.

12Step 7 · API keys & the server proxy

If your layer needs a private key, you have three integration points:

  1. POWER UP panel — declare your provider in src/keySetup.js so users can paste a key in-app.
  2. Server proxy route — add a route under the dev server that injects the key from .env or the macOS Keychain, never exposing it to the browser.
  3. Layer flag — set requiresKey: 'yourkey' so the panel disables the layer until a key is present.

Declaring the key slot

// src/keySetup.js
export const PROVIDERS = [
  { id: 'cesium',     label: 'Cesium ion',        tier: 'free',   envVar: 'CESIUM_ION_TOKEN' },
  { id: 'google',     label: 'Google Maps',      tier: 'metered', envVar: 'GOOGLE_MAPS_KEY' },
  { id: 'aisstream', label: 'AISStream',        tier: 'free',   envVar: 'AISSTREAM_KEY' },
  { id: 'yourkey',   label: 'Your Provider',    tier: 'free',   envVar: 'YOUR_PROVIDER_KEY' },  // ← add
];

Server proxy

// server/routes/yourkey.js  (Vite dev middleware)
import { ssrfGuard, cappedFetch } from './util.js';

export async function handle(req, res) {
  const key = process.env.YOUR_PROVIDER_KEY;
  if (!key) return res.status(503).json({ error: 'not_configured' });

  const target = ssrfGuard(req.query.url);   // block 169.254/16, RFC1918, etc.
  const upstream = await cappedFetch(target, {
    headers: { Authorization: 'Bearer ' + key },
    maxBytes: 2_000_000,                  // response cap
    timeoutMs: 8000,
  });

  res.json(upstream);                         // sanitized — no key in body
}
Threat model The dev server binds to localhost by default. If you opt in to LAN sharing, any reachable user can call your brokered endpoints. Set per-IP throttles (GEV_RATELIMIT_*), configure provider quotas/budgets, and never expose the Provider Settings panel remotely — it's disabled when --host 0.0.0.0 is set. App-level throttles are not billing caps.

13Step 8 · Voice tools (optional)

The voice agent under src/voice/ is an OpenAI Realtime session with 28 tools across four jobs: direct it, annotate it, interrogate it, operate it. Adding your own tool is the cleanest way to make your layer talkable.

Declare the tool

// src/voice/tools/shipSpottersQuery.js
export const shipSpottersQuery = {
  name: 'ship_spotters_query',
  description: 'Query the community AIS layer. Use when the user asks about ships near a place, by class, by destination, or by name.',
  parameters: {
    type: 'object',
    properties: {
      place:    { type: 'string', description: 'A location name or "current view".' },
      shipClass:{ type: 'string', enum: ['tanker', 'cargo', 'passenger', 'all'] },
      minSpeed: { type: 'number', description: 'Minimum speed in knots.' },
    },
    required: ['place'],
  },

  async run(args, ctx) {
    const layer = ctx.orch.getLayer('ship-spotters');
    if (!layer || !layer._enabled) {
      return { ok: false, reason: 'layer_disabled' };
    }

    const center = await ctx.geocode(args.place);
    const contacts = layer.contactsNearby(center.lat, center.lon, 250);

    const filtered = contacts
      .filter(c => !args.shipClass || args.shipClass === 'all' || c.class === args.shipClass)
      .filter(c => !args.minSpeed || c.sog >= args.minSpeed)
      .slice(0, 12);

    return {
      ok: true,
      spoken: `${filtered.length} ships near ${args.place}`,
      contacts: filtered.map(c => ({ name: c.name, mmsi: c.mmsi, sog: c.sog, destination: c.destination })),
    };
  },
};

Register it

// src/voice/index.js
import { shipSpottersQuery } from './tools/shipSpottersQuery.js';

export const TOOLS = [
  // …existing 28…
  shipSpottersQuery,
];

Now you can say "how many tankers are near Rotterdam on the community feed?" and get a spoken count plus a populated contacts card. The agent is instructed to only confirm actions that succeeded — your tool's ok: false paths keep it honest.

Honest and secure The agent only confirms actions that succeeded. Your OPENAI_API_KEY never touches the browser; the client only gets a short-lived session token. Layer keys you read out of ctx.orch are the same keys the rest of the app uses — never re-fetch from process.env in a voice tool.

14Step 9 · Share-link state

Every layer's filters, density sliders, and tracked contact serialize into the URL via serializeState / deserializeState. A live tracked contact is a handoff, not a bookmark — when someone opens your share link, the contact keeps moving. 

serializeState() {
  return {
    enabled: this._enabled,
    filters: { class: this._filterClass, density: this._density },
    trackedId: this._trackedId ?? null,
  };
},

deserializeState(s) {
  if (s?.filters) {
    this._filterClass = s.filters.class;
    this._density    = s.filters.density;
  }
  if (s?.enabled) this.enable();
  if (s?.trackedId) this._pendingTrackId = s.trackedId;
},

The orchestrator handles URL parsing and dispatch — you just provide the snapshot. Round-trip test by enabling your layer, tracking a contact, copying the URL, and opening it in a fresh tab.

15Best practices

Performance

  • Cap entities. Set maxEntities and cull outside the viewport. The flights layer only shows contacts in or near the current view — thousands globally, hundreds rendered.
  • Interpolate, don't snap. Live feeds arrive every 15–30s; render one interval behind real time and lerp between known fixes. Dead reckon the gaps.
  • Cache aggressively. Disk-cache static lists (TLEs, bundled data). Memoize geocoded place names. The OpenSky credit governor and TomTom daily tile budget are reference patterns.
  • Heights on the real ground. Entity heights are aligned to work with Google 3D tiles so aircraft park on aprons and cameras stand on street corners. Use HeightReference.CLAMP_TO_GROUND for ground-fixed entities.

Security

  • Broker every private key server-side. The only keys the browser may see are Google Maps and Cesium ion — both URL-restricted at the provider.
  • SSRF-protect every proxy. Block link-local, RFC1918, and loopback targets. Cap response size. Sanitize errors so the key never leaks in a stack trace.
  • Per-IP throttles. Set GEV_RATELIMIT_* for any provider you broker. App throttles are not billing caps — set provider budgets too.
  • Disable Provider Settings on shared instances. The panel auto-disables when --host 0.0.0.0 is set; don't override this.

Honesty

  • Label modeled data. Space Missions replay trajectories are labeled RECONSTRUCTED ESTIMATE in the UI. CCTV camera poses are estimated priors you calibrate by dragging a gizmo. If your layer is inferred, modeled, or coarse, say so — in the panel and in the telemetry card.
  • Stale data is okay; silent stale data is not. Surface the timestamp of the last good fix. If your feed goes dark, show "feed degraded" rather than freeze the world.
  • No person-tracking. Don't merge PRs that build named-person search, face recognition, or individual tracking. People are not a query type.

17Testing & debugging

The project ships a small dev ergonomics surface — use it.

  • npm run doctor — reports Node/npm readiness, primary provider routes, and where each configured provider was found (without printing credential values).
  • npm run dev — Vite dev server on http://localhost:4173.
  • ./scripts/dev-fresh.sh (macOS) — clears the Vite cache and pulls configured keys straight from Keychain. Starts keyless too.
  • ?setup=1 — reopens the POWER UP panel if a compact layout hides it.
  • ?layer=ship-spotters&track=<id> — share-link round-trip test for your layer.
Work with a coding agent The maintainer explicitly recommends cloning the repo into Cursor / Claude Code / Codex / Antigravity and describing the layer you want in natural language. The repo's vanilla-JS shape is intentionally agent-friendly — small files, no framework magic, no hidden conventions. State what your layer does, what feed it reads, and what it should look like; let the agent wire it.

18Submitting a PR

The project welcomes community layers — ALPR cameras and SDR radio are already in flight as PRs.

  1. Open an issue first describing the layer and the feed. The maintainers will flag duplicates, key-handling concerns, or scope issues before you write code.
  2. Fork, branch feat/layer-<name>, implement against this manual.
  3. Drop a README.md in local_data/<your_dataset>/ with provenance, license, and last-updated date.
  4. If you added a key, update SECURITY.md with the new brokered route and any LAN-sharing implications.
  5. Include at least one share-link round-trip test in your PR description (URL with your layer enabled + a tracked contact).
  6. Don't cross the line — person-tracking, face recognition, and named-person search won't merge.

19Ship checklist

Before you open the PR
  • Layer module lives at src/data/<name>.js and exports the full lifecycle contract.
  • Registered in src/main.js; appears in the LAYERS panel with name, icon, description.
  • Uses iconOrientation.js for world-stable headings (no spinning, no viewport-locking).
  • Interpolates between fixes — smooth motion, not snap-step.
  • Respects maxEntities and viewport culling.
  • Labels modeled/inferred data honestly (RECONSTRUCTED ESTIMATE, estimated prior, etc.).
  • Private keys brokered server-side; SSRF guard, response caps, sanitized errors.
  • Static data in local_data/ with provenance + license.
  • Optional: voice tool registered in src/voice/ with honest ok: false paths.
  • Optional: share-link state serializes filters + tracked contact and round-trips.
  • Does not enable named-person search, face recognition, or individual tracking.

## 1. Overview

### 1.1 What MyMine is used for

MyMine is used for **monitoring the work on site, and letting the investor, the site team and outside experts see the same live picture of the mine.**

It does this by building a 3D digital twin of the mine from the site's existing survey, CAD and GIS files, then letting multiple people open that twin at the same time, on whatever device they have, whether they are in the pit, in an office or in another country.

### 1.2 Core value proposition

| Value                          | What it means in practice                                                             |
| ------------------------------ | ------------------------------------------------------------------------------------- |
| One agreed picture of the mine | Everyone works from the same 3D model rather than separate maps, drawings and reports |
| Remote presence                | The investor sees the site without flying in                                          |
| Decisions on current state     | Live data feeds are shown in the model with timestamps                                |
| Resilience                     | Sessions continue through internet outages via an on-site edge node                   |
| Fewer expert call-outs         | OEM and specialist experts can join remotely and annotate the model                   |
| Clearer safety communication   | Hazard zones and exclusion areas are shown in 3D before crews enter                   |

### 1.3 What MyMine is not

- It is **not a certified safety system**.
- It is **not an early-warning system** for ground movement.
- It does **not replace** planning, fleet management or SCADA systems.

## 4. Feature Reference

### 4.1 AR Digital Twin

**Status:** Stated

**Description:** An interactive 3D model of the mine, built from the site's existing survey, CAD and GIS files.

**Inputs:** Site survey data, CAD files, GIS files.

**What users can do:**

- Open and navigate the 3D model of the mine.
- View it in a browser, on a tablet, or in a headset.
- Use it as the common reference for every conversation about the site.

**Benefit:** One agreed picture of the mine.

**Notes to confirm:** Supported file formats, coordinate systems, model size limits, processing time from raw files to usable twin.

---

### 4.2 Drone / LiDAR Updates

**Status:** Unverified

**Description:** The model is refreshed from drone or LiDAR surveys. The model shows the date of the latest survey update so users know how current it is.

**What users can do:**

- See the date of the latest survey update displayed with the model.
- Understand whether they are looking at yesterday's or last month's terrain.

**Benefit:** Everyone knows how current the model is.

**Guidance:** The "latest survey date" display is the key trust signal. Never imply the model is live to the minute; only the data feeds (see 4.5) carry live timestamps.

**Notes to confirm:** Update frequency, supported survey formats, whether updates are manual or automated, time from flight to model refresh.

---

### 4.3 Multi-Device Access and Multi-User Collaboration

**Status:** Stated

**Description:** Several people join one shared session from different devices at the same time.

**Example configuration:**

| Participant       | Device             |
| ----------------- | ------------------ |
| Yaw               | Tablet, in the pit |
| Geotech           | Headset            |
| GM                | Browser            |
| Naledi (investor) | Browser            |

**What users can do:**

- Join the same session regardless of location or device type.
- See the same model state and each other's annotations.

**Benefit:** The investor sees the site without flying in.

**Notes to confirm:** Maximum simultaneous users, supported headsets and browsers, bandwidth requirements, how participants are invited and authenticated.

---

### 4.4 Importing Layers from Other Tools

**Status:** Unverified (pre-load layers if import is not available)

**Description:** Layers produced in other project tools can be switched on inside the twin so the model carries the whole history of the project.

**Example layers (from the walkthrough):**

| Layer                      | Source tool  | Content                                      |
| -------------------------- | ------------ | -------------------------------------------- |
| District picture           | MineSentinel | Wider regional context                       |
| Boundary and forest buffer | MineAsk      | Licence boundary and protected forest buffer |
| Targets                    | TerraPulse   | Exploration or drilling targets              |

**What users can do:**

- Switch inherited layers on and off during a session.
- Overlay earlier project work on the current mine model.

**Benefit:** The whole history of the project in one model.

**Guidance:** If live import is not confirmed, **pre-load the layers** into the model before any session and describe them as "available in the model" rather than "imported on the spot".

---

### 4.5 Real-Time Data Streaming

**Status:** Stated; pilots start with 1 to 2 sources

**Description:** Live data feeds can be switched on inside the twin, each with a timestamp.

**Examples:** Equipment positions; a sensor reading.

**What users can do:**

- Switch on one or two live feeds.
- Read the timestamp to know how recent each value is.

**Benefit:** Decisions on the current state of the site.

**Guidance:** Do not promise broad integration. Position as "starting with one or two sources per pilot."

**Notes to confirm:** Supported protocols and sources, refresh rate, behaviour when a feed drops, who sets up each feed.

---

### 4.6 Annotation and Highlighting (Multi-User Collaboration)

**Status:** Stated

**Description:** Participants highlight and annotate parts of the model. All annotations are visible to every participant in real time.

**Typical use:** Highlight the bench being mined this week and discuss the next mining sequence.

**What users can do:**

- Circle or highlight a bench or area.
- Discuss sequencing with the geotech.
- Let the investor see every annotation as it is made.

**Benefit:** Shorter reviews; one shared understanding.

---

### 4.7 Plan-vs-Actual Overlay

**Status:** **Roadmap**

**Description (planned):** Compare the mine plan with what was actually mined.

**Guidance:** **Not demonstrated.** Say it is on the roadmap. Do not show mock-ups as working functionality.

---

### 4.8 Hybrid Edge Sync

**Status:** Stated

**Description:** If the site's internet link drops, the session keeps running on an **on-site edge node** and syncs back when the link returns.

**What users can do:**

- Continue monitoring on site during an outage.
- Rely on automatic sync when connectivity returns.

**Benefit:** Monitoring continues through connectivity outages.

**Notes to confirm:** Edge hardware requirements, what is available offline (full model vs cached portion), conflict handling when offline edits sync, whether remote participants can still join during an outage (assumption: no).

---

### 4.9 Remote Expert Assist

**Status:** Unverified (use a recording unless confirmed)

**Description:** When equipment fails, an external expert (for example the OEM's specialist, abroad) joins the session and annotates the failed part in the model.

**Example:** The crusher trips; the OEM's expert joins from abroad and marks up the failed component.

**What users can do:**

- Invite a remote expert into a live session.
- See the expert's annotations on the failed part in the model.

**Benefit:** Fewer expert call-outs; less downtime.

**Guidance:** Show only from a recording unless confirmed working end to end.

---

### 4.10 Hazard Briefing and AR Training

**Status:** Shared sessions stated; training content unverified

**Description:** Walk new crew through hazard zones and exclusion areas in 3D before they enter the site.

**What users can do:**

- Lead a group through the 3D model, pointing out hazard zones and exclusion areas.
- Use the shared session as an induction aid.

**Benefit:** Shorter inductions; clearer hazard communication.

**Guidance:** The shared-session briefing can be presented as available. Packaged AR training modules, assessments or certification content must not be promised until confirmed.

---

### 4.11 Slope and Ground Monitoring Overlay

**Status:** Unverified

**Description:** Ground-movement data displayed on the pit wall inside the model so the geotech and operations can agree an exclusion zone.

**Benefit:** Faster shared understanding.

**Important:** This is **not an early-warning system.** Do not describe it as predicting, alarming on, or preventing slope failure.

---

### 4.12 Audit Trail

**Status:** **Roadmap**

**Description (planned):** Record the session's decisions and actions.

**Guidance:** Mention as roadmap only. Do not claim that decisions are currently recorded or that records are legally reliable.

## 5. Usage Guide: Step-by-Step Walkthrough

This is the end-to-end flow of a MyMine session, in order.

### Step 1: Open the 3D twin

**Who:** Yaw
**Feature:** AR digital twin

1. Yaw opens MyMine and loads the site's twin (built from survey, CAD and GIS files).
2. Confirm the correct site and model version is loaded.

**Outcome:** One agreed picture of the mine.

### Step 2: Show the latest survey date

**Who:** Yaw
**Feature:** Drone/LiDAR updates *(Unverified)*

1. Yaw points out the date of the latest survey update shown with the model.
2. Participants note how current the terrain is.

**Outcome:** Everyone knows how current the model is.

### Step 3: Everyone joins one session

**Who:** Naledi, Yaw, geotech, GM
**Features:** Multi-device access; multi-user collaboration

1. Yaw joins on a tablet in the pit.
2. The geotech joins in a headset.
3. The GM and Naledi join through browsers.
4. Confirm everyone sees the same view.

**Outcome:** The investor sees the site without flying in.

### Step 4: Switch on inherited layers

**Who:** Yaw
**Feature:** Importing layers from other tools *(Unverified; pre-load if import isn't available)*

1. Yaw switches on the MineSentinel district picture.
2. Yaw switches on the MineAsk boundary and forest buffer.
3. Yaw switches on the TerraPulse targets.

**Outcome:** The whole history of the project in one model.

### Step 5: Switch on live data feeds

**Who:** Yaw
**Feature:** Real-time data streaming *(Stated; pilots start with 1 to 2 sources)*

1. Yaw turns on one or two feeds, for example equipment positions or a sensor reading.
2. Participants check the timestamps on each feed.

**Outcome:** Decisions on the current state of the site.

### Step 6: Highlight the bench and discuss sequence

**Who:** Yaw and geotech (Naledi observes)
**Feature:** Multi-user collaboration

1. Yaw and the geotech highlight the bench being mined this week.
2. They discuss the next mining sequence.
3. Naledi sees every annotation as it is made.

**Outcome:** Shorter reviews; one shared understanding.

### Step 7: Compare plan with actual

**Who:** Yaw
**Feature:** Plan-vs-actual overlay *(Roadmap)*

Do not demonstrate. State that this is on the roadmap.

### Step 8: Connectivity outage

**Who:** Site team
**Feature:** Hybrid edge sync

1. The site's internet link drops.
2. The session continues on the on-site edge node.
3. When the link returns, data syncs.

**Outcome:** Monitoring continues through connectivity outages.

### Step 9: Breakdown with remote expert

**Who:** Maintenance, OEM expert
**Feature:** Remote expert assist *(Unverified; use a recording unless confirmed)*

1. The crusher trips.
2. The OEM's expert joins from abroad.
3. The expert annotates the failed part in the model.

**Outcome:** Fewer expert call-outs; less downtime.

### Step 10: Hazard briefing for new crew

**Who:** Abena (HSE)
**Feature:** Hazard briefing; AR training *(Shared sessions stated; training content unverified)*

1. Abena opens the model with the new crew.
2. She walks them through hazard zones and exclusion areas in 3D before they enter.

**Outcome:** Shorter inductions; clearer hazard communication.

### Step 11: Ground-movement review

**Who:** Geotech
**Feature:** Slope and ground monitoring overlay *(Unverified)*

1. The geotech shows ground-movement data on the pit wall.
2. Geotech and operations agree an exclusion zone.

**Outcome:** Faster shared understanding. *(Not an early-warning system.)*

### Step 12: Record decisions

**Who:** Yaw
**Feature:** Audit trail *(Roadmap)*

Mention as roadmap only.

## 6. Scenario Playbooks

### 6.1 Investor Oversight Session

**Goal:** Let the investor monitor the asset and verify commitments without travelling.

|               |                                                                                                             |
| ------------- | ----------------------------------------------------------------------------------------------------------- |
| Participants  | Investor (browser), GM (browser), site operator (tablet), geotech (headset)                                 |
| Features used | Digital twin, multi-device access, imported layers, live feeds, annotation                                  |
| Flow          | Open twin, confirm survey date, switch on project layers, switch on one live feed, review the current bench |

**Example check:** The investor asks whether the next bench is inside the line drawn around the forest. The operator switches on the MineAsk layer, the forest buffer appears, and the answer is visible in the model (in the walkthrough: untouched, two hundred metres east).

**What this demonstrates:** Commitments made at the start of the project (such as protecting the forest buffer) can still be seen and checked.

### 6.2 Weekly Planning Review

**Goal:** Agree the next mining sequence faster.

1. Open the twin and confirm the survey date.
2. Switch on the layers relevant to this bench.
3. Highlight the bench being mined this week.
4. Discuss the sequence; annotate decisions in the model.
5. Everyone, including remote participants, sees the same annotations.

### 6.3 Connectivity Outage

**Goal:** Keep monitoring running when the link drops.

1. Session is running normally.
2. Internet link drops. The session continues on the on-site edge node.
3. Site team keeps working.
4. Link returns. Data syncs automatically.

### 6.4 Equipment Breakdown with Remote Expert

**Goal:** Reduce downtime and expert travel.

1. Equipment trips (example: crusher).
2. Maintenance opens the twin at the equipment.
3. OEM expert joins remotely.
4. Expert annotates the failed part.
5. Maintenance proceeds with the repair guided by the annotation.

*Present from a recording unless confirmed.*

### 6.5 New Crew Hazard Induction

**Goal:** Shorter, clearer inductions.

1. HSE opens the twin with the new crew.
2. Walk through hazard zones and exclusion areas in 3D.
3. Confirm understanding before the crew enters the site.

### 6.6 Ground-Movement Exclusion Zone Review

**Goal:** Reach a shared understanding quickly.

1. Geotech shows ground-movement data on the pit wall.
2. Geotech and operations agree an exclusion zone.
3. Zone is annotated in the model.

*Not an early-warning system. Does not replace the site's geotechnical monitoring and safety procedures.*

## 9. Pilot and Deployment Guidance

### 9.1 Recommended pilot scope

- **One site**, one twin.
- **One to two live data sources** (for example equipment positions and one sensor).
- Start with the **Stated** features: twin, multi-device collaboration, annotation, live feeds, edge sync, shared hazard briefings.
- Add unverified features only after they are confirmed.

### 9.2 Data and inputs needed

| Input                                                       | Purpose                            |
| ----------------------------------------------------------- | ---------------------------------- |
| Site survey data                                            | Base terrain for the twin          |
| CAD files                                                   | Infrastructure and design geometry |
| GIS files                                                   | Boundaries, regional context       |
| Drone/LiDAR surveys (if available)                          | Model refresh                      |
| Layers from other tools (MineSentinel, MineAsk, TerraPulse) | Project history                    |
| Live feed access (1 to 2 sources)                           | Real-time data                     |

### 9.3 Infrastructure

- **On-site edge node** for hybrid edge sync.
- Devices for each persona: tablets for site, browsers for remote viewers, headsets for specialists where used.
- Network connectivity for remote participants (normal operation).

### 9.4 Suggested rollout sequence

1. Build the twin and confirm the survey date display.
2. Set up multi-user sessions and test all device types together.
3. Pre-load project layers.
4. Connect the first live feed, then the second.
5. Test the edge node by simulating a connectivity drop.
6. Run a real planning review.
7. Run hazard briefings with HSE.
8. Evaluate unverified features (remote assist, ground monitoring, layer import) and decide what to enable.

### 9.5 Success measures to track in a pilot

- Time taken for planning reviews, before and after.
- Time taken for HSE inductions, before and after.
- Number of expert callouts avoided.
- Number of investor/remote sessions held in place of site visits.
- Session uptime during connectivity outages.
- User adoption by role.

## 10. Limitations and Honesty Notes

1. **Core features are product-owner statements.** They have not yet been confirmed in a demo.
2. **Unverified or roadmap:** remote assist, plan-vs-actual, layer import, ground monitoring and audit trail.
3. **Not a certified safety system.** MyMine must not be relied on for safety-critical decisions.
4. **Not an early-warning system.** The ground monitoring overlay supports shared understanding only.
5. **Does not replace** planning, fleet management or SCADA systems.
6. **Live data is limited at the start.** Pilots begin with one or two sources.
7. **Value figures are illustrative.** They come from the product team's base case, not from measurement.
8. **Use recordings** for anything unconfirmed, and say clearly that they are recordings.

## 12. Glossary

| Term                       | Meaning                                                                                   |
| -------------------------- | ----------------------------------------------------------------------------------------- |
| **Digital twin**     | A 3D model of the mine that mirrors the physical site                                     |
| **AR**               | Augmented reality: viewing digital content overlaid on the real or modelled environment   |
| **CAD**              | Computer-aided design files (engineering drawings and models)                             |
| **GIS**              | Geographic information system files (spatial and map data)                                |
| **LiDAR**            | Laser-based surveying that produces detailed 3D terrain measurements                      |
| **Bench**            | A horizontal step in an open-pit mine face from which material is extracted               |
| **Edge node**        | A computer on the mine site that keeps the session running when the internet is down      |
| **Hybrid edge sync** | Local operation on the edge node plus automatic sync with the cloud when the link returns |
| **OEM**              | Original equipment manufacturer                                                           |
| **HSE**              | Health, Safety and Environment                                                            |
| **SCADA**            | Supervisory control and data acquisition: industrial control and monitoring systems       |
| **Geotech**          | Geotechnical engineer, responsible for ground and slope stability                         |
| **Exclusion zone**   | An area people and equipment must not enter                                               |
| **Forest buffer**    | A protected strip around a forest, set as a project commitment                            |
| **Layer**            | A switchable overlay of information in the 3D model                                       |
